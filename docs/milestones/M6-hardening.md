# M6 — Hardening, deployment, documentation: status summary

Date: 2026-10-18

## Completed functionality
- **Risk flags** on listing details: rule-based, with severity. Details are in `M5-assistant.md`.
- **Official portal links** for Bhoomi, Kaveri, RERA Karnataka and HDMC, in the glossary and in document answers.
  They were checked through secondary sources, because the government sites could not be opened from the build
  environment.
- **Security hardening:**
  - Failed logins are limited to 10 per minute per client and email, then 429. Successful logins are not counted.
  - Every API response sends `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and
    `X-Frame-Options: DENY`. The frontend's pages send `nosniff`, `DENY`, a strict referrer policy and a
    Permissions-Policy that blocks camera, microphone and geolocation (`next.config.mjs`).
  - Behind Render's proxy, the client address comes from `X-Forwarded-For` only when `TRUST_PROXY_HEADERS` is set.
- **Render deployment** (`render.yaml`, `DEPLOY.md`), all on free plans:
  - Postgres 16; the FastAPI service with health check `/api/v1/health`; the Next.js service.
  - `JWT_SECRET` and `SEED_DEMO_PASSWORD` are generated by Render. `ANTHROPIC_API_KEY` is optional and entered at
    deploy time.
  - `backend/scripts/render_start.sh` runs `alembic upgrade head`, then the idempotent seed, then uvicorn with proxy
    headers.
  - Render's `postgresql://` URL is converted to the psycopg driver in config.
  - The frontend forwards `/api/v1/*` and `/media/*` to the API at request time (`frontend/src/lib/proxy.ts`). There is
    no CORS setup and no API URL in the build. The target comes from `API_PROXY_URL`, or from `API_HOST`, which the
    Blueprint copies from the API service.
  - If the target is missing the proxy answers 503 `proxy_not_configured`; if the API is asleep, 502
    `backend_unreachable` with a "try again in a minute" message.
- **Image storage on the free tier.** Photos stay on the API's local disk. This is temporary on Render's free plan
  and is documented as such. The demo listings have no photos, so the demo is unaffected.
- **Integration test of the full demo.** `frontend/e2e/demo.spec.ts` runs specification steps 1–15 in a real browser
  against the live API and a production build.
- **Documentation:**
  - `DEPLOY.md`.
  - `docs/api.md`, with real request and response examples for every endpoint.
  - This summary and `M5-assistant.md`.
  - `docs/report/`: `report_material.md`, `demo_script.md`, `viva_qa.md` and `limitations.md`.
  - The README and the requirements checklist, updated.

## Defaults chosen where the brief left a detail open
- **Same-origin proxy rather than CORS.** Render's free services get their URLs at creation time. Proxying means the
  browser needs no API URL and the build never depends on one.
- **Migrate and seed on every start, not in a pre-deploy step.** Render's pre-deploy command is not available on free
  instances. Both steps are idempotent.
- **Generated demo password on Render.** A public URL should not use the local default `DemoPass123`.
