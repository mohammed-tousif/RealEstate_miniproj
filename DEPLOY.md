# Deploying PropWise AI to Render (free tier)

`render.yaml` is a Render Blueprint. It creates three resources, all on the free plan:

| Resource | What it runs |
|---|---|
| `propwise-db` | Render PostgreSQL 16 |
| `propwise-api` | FastAPI on Python 3.11. Each start runs `alembic upgrade head`, loads the synthetic demo data and the 22 real imported listings if they are missing, then starts uvicorn (`backend/scripts/render_start.sh`). Health check: `/api/v1/health` |
| `propwise-web` | Next.js (`next start`). The browser only talks to this service; it forwards `/api/v1/*` and `/media/*` to the API (`frontend/src/lib/proxy.ts`) |

Because the frontend proxies the API on the same origin, there is no CORS setting and no API URL baked into the build.

## Steps

1. Push this folder to a GitHub repository (private is fine). `render.yaml` must be at the repository root.
2. In the Render Dashboard choose **New → Blueprint**, connect GitHub and pick the repository.
3. Render lists the three resources and asks for `ANTHROPIC_API_KEY`:
   - leave it empty to run the assistant in the labelled **Basic search mode** (rule-based, no AI, no cost), or
   - paste an Anthropic API key to enable the AI assistant. Calls are billed to that key; the defaults are
     `LLM_MODEL=claude-opus-5-5` with `LLM_EFFORT=low`, at most 5 tool rounds per question, and 12 questions per
     client per minute.
4. Click **Apply**. The first build takes several minutes (Python ML libraries and the Next.js build).
5. Open the `propwise-web` URL (`https://propwise-web….onrender.com`).

Check the API directly at `https://<propwise-api host>/api/v1/health`. It should report
`"database": true` and `"price_model_loaded": true`.

## Demo accounts

The seed creates `admin@demo.propwise.example`, `seller1@…`, `seller2@…`, `seller3@…` and `buyer@demo.propwise.example`.
Their password is the generated `SEED_DEMO_PASSWORD`: open **propwise-api → Environment** in the Dashboard to read it.
On a public URL, do not change it to the local default `DemoPass123`.

## Environment variables

| Service | Variable | Value |
|---|---|---|
| api | `DATABASE_URL` | from `propwise-db` (a `postgresql://` URL is converted to the psycopg driver automatically) |
| api | `JWT_SECRET`, `SEED_DEMO_PASSWORD` | generated by Render |
| api | `APP_ENV=production` | refuses to start without `JWT_SECRET` |
| api | `TRUST_PROXY_HEADERS=true` | per-client rate limits use `X-Forwarded-For`, since requests arrive through the frontend |
| api | `ANTHROPIC_API_KEY`, `LLM_MODEL`, `LLM_EFFORT`, `AI_RATE_LIMIT_PER_MINUTE` | assistant settings |
| web | `NEXT_PUBLIC_API_BASE_URL=/` | browser calls the frontend's own `/api/v1` |
| web | `API_HOST` | the API's public hostname, copied from `propwise-api` |

If the frontend shows "API_PROXY_URL or API_HOST is not set", set `API_PROXY_URL=https://<propwise-api host>` on
`propwise-web` by hand and redeploy it.

## Free-tier behaviour to expect

- **Sleeping services.** Free web services stop after about 15 minutes without traffic. The next visit wakes them,
  which takes roughly a minute; during that time the site may show "The PropWise API is not reachable". Open the
  site a minute before a demo.
- **Uploaded photos are temporary.** Free services have no persistent disk, so photos sellers upload are lost when
  the API restarts or redeploys. The demo listings have no photos (the cards draw an illustration), and listing data
  lives in Postgres, so it is kept. For permanent photos, attach a paid Render disk at `backend/storage` or move
  storage to an object store (the storage layer is in `backend/app/services/storage.py`).
- **Free Postgres has a time limit.** Render expires free databases after a fixed period; check Render's current
  free-tier terms and upgrade or recreate the database before then. A new database is migrated and re-seeded on the
  next API start.
- **One API instance.** Rate limits are kept in memory, which is right for a single instance.

## Updating

Pushing to the repository's default branch redeploys both services. Migrations run on every API start, and the
seed step skips data that is already loaded.

## Running the same thing locally

```bash
cd backend && DATABASE_URL=postgresql://propwise:propwise@localhost:5432/propwise APP_ENV=production \
  JWT_SECRET=$(python -c "import secrets;print(secrets.token_urlsafe(48))") bash scripts/render_start.sh
cd frontend && NEXT_PUBLIC_API_BASE_URL=/ npm run build && API_PROXY_URL=http://127.0.0.1:8000 npx next start -p 3000
```
